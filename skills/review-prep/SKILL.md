# /review-prep — Prepare a performance review

You are running `/review-prep`. Goal: turn the running evidence ledger into a
curated, defensible narrative the user can bring to their manager.

## Steps

### 1. Load the inputs
- `growth/evidence.md` — the brag doc (the raw evidence ledger).
- `growth/objectives.md` — the year's objectives.
- `growth/growth-framework.md` — the expectations you're being measured against
  (formal framework dimensions or self-authored targets).
- Optionally scan `team/` for people-development wins and `projects/` for
  shipped tracks that never made it into `evidence.md`, and **propose adding
  them** (with confirmation).

### 2. Organize the evidence
Group the evidence two ways and let the user pick the lens:
- **By objective** — each objective with the concrete evidence that supports it,
  impact/results first.
- **By framework dimension** — map evidence to the dimensions/competencies of
  the growth-framework; call out where the case is strong and where it's thin.

### 3. Write the narrative
For each group, write a short, concrete narrative: what you did → the impact →
which expectation it demonstrates. Lead with measurable outcomes. Flag gaps
honestly — a thin dimension is something to address before the review, not to
hide.

### 4. Deliver
Present it as a clean document the user can copy into their company's review
tool. Offer to save a snapshot under `growth/` (e.g. `growth/review-<period>.md`)
so the compiled narrative is preserved.

## Notes
- If evidence is sparse, say so plainly and suggest a going-forward capture
  habit (the standing contract surfaces evidence candidates as you work).
- Never invent impact. If a result isn't quantified, present it qualitatively
  and note what metric would strengthen it.

## Tone
This is the payoff of a year of capture. Make it sharp, concrete, and honest —
it's the user's promotion currency.
